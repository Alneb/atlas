# The terminal: how it draws, its colours, its fonts, its keys

The terminal pane (`ui/src/panes/Terminal.svelte`) is xterm.js 6 over a websocket to the core's PTY (`crates/atlas-core/src/pty.rs`). The Claude pane is the same pane with the `claude` preset. This page is the one place for why the terminal looks and behaves the way it does; keys are in `KEYS.md`, the PTY protocol in `ARCHITECTURE.md`.

## What was reported
The terminal's colours needed work and some things rendered oddly: Claude Code's `|-` box lines and the light-theme colours. LaTeX could render in Claude's output, Claude Code could look less like a raw terminal, and focus sometimes did not follow.

## Causes found, and what changed
- **Claude's `⎿` and other symbols.** The bundled JetBrains Mono (`@fontsource/jetbrains-mono`) ships only its Latin, Latin-ext, Cyrillic, Greek and Vietnamese subsets: no box drawing, no arrows, no `⎿` (U+23BF), `⏺` (U+23FA), `✻` (U+273B) and the rest of Claude Code's status symbols. The browser then took each missing glyph from whatever system font had it — on a Fedora desktop sometimes a CJK font (Harano Aji, Noto Sans CJK), which draws them double width and on another baseline. Of the installed fonts only **Adwaita Mono** (GNOME's Iosevka-based monospace, SIL OFL 1.1) covers all of them. Atlas now bundles **Atlas Term Symbols**: a subset of Adwaita Mono (regular and bold; U+2000–206F, 2190–23FF, 2460–24FF, 2500–27BF, 2900–29FF, 2B00–2BFF; ~49 KB each as woff2), renamed as the OFL asks, with the licence beside it (`ui/src/assets/fonts/`). Its advance is 0.6 em, the same as JetBrains Mono, so the symbols keep the cell grid. It is second in `--font-mono` (`tokens.css`), so code blocks and the editor get the same symbols. Rebuild it with `python3 -m fontTools.subset /usr/share/fonts/adwaita-mono-fonts/AdwaitaMono-Regular.ttf --unicodes=… --flavor=woff2 --layout-features= --no-hinting --desubroutinize`, then rename the name table entries 1, 3, 4, 6, 16 (the transcript has the exact script).
- **Gaps in Claude's `│` lines.** With `lineHeight: 1.25` the DOM renderer draws `│` from the font, one glyph per row, with a gap between rows. The terminal now loads **`@xterm/addon-webgl`**, which draws box-drawing and block characters itself to the full cell, so lines join. When WebGL is missing or its context is lost, xterm falls back to its DOM renderer. Setting: `[terminal] renderer = "gpu" | "text"` (default `gpu`; `text` keeps the terminal's text in the page — the e2e workspace uses it, since several specs read `.xterm-rows`).
- **Light mode colours.** ANSI black was `--term-black` = `#e3e5ea`, a light grey on the white background, so anything printed in black vanished; ANSI white was `--text-muted`. The bright colours were the same as the normal ones (bold / dim distinctions in TUIs disappeared). There is now a real 16-colour palette per theme, `--ansi-<colour>` and `--ansi-bright-<colour>` in `tokens.css` (dark: Atlas's hues with lighter brights; light: GitHub-light-like, dark enough on white), and a **minimum contrast** (`--term-contrast`: 4.5 in light, 3 in dark) that xterm applies to every colour, truecolour included, so a program that assumes a dark background stays readable on the light theme. An imported VS Code theme sets the same tokens from its `terminal.ansi*` colours (`vscode-theme.ts`).
- **Focus.** Two holes closed: a click on the pane's padding (outside xterm's own element) did nothing — it now focuses the terminal; a click on the tab of the pane already in front fired no activation, so the keys stayed on the tab — the dock now hands them to the pane (`giveKeys` in `dock.ts`, shared with `show()`). Keys inside a focused terminal: `KEYS.md` (the shell keeps every non-Super key).

Test: `ui/tests/terminal-looks.spec.ts` (the symbols font loads and has JetBrains Mono's width; the padding takes focus).

## A reload does not end the terminals

**What happened**: the terminals reset. A commit fired the `post-commit` hook (`auto-install.sh`), the install replaced `~/.local/share/atlas/ui`, and `ui-reload.ts` reloaded the open window. The reload closed every `/api/pty` socket, and `pty.rs` killed each child with its socket: a Claude Code session in an Atlas terminal (and the agents it was running) died mid-turn and came back with `--resume`, its running work and queued messages lost. Every commit by any agent did it, and the build id was the `index.html` modification time, so even a docs-only commit reloaded the window.

**What changed.**
- `pty.rs`: a terminal belongs to the core, not to its socket (`Sessions`, kept in the server's state). A socket opened with `key` (this window's id from `sessionStorage` + the tab's id) takes over that key's terminal if it is still running: it gets the last 1 MB of output first, then a resize jiggle that makes a full-screen program (Claude) repaint. A socket that drops without a word leaves the program running for `GRACE` (10 minutes); the text frame `"end"` (the tab was closed; `ptyEnd` in `api.ts`) kills it at once, as does the program's own exit. A socket without a key behaves as before (dies with its socket).
- `Terminal.svelte`: passes the key; on dispose it says "end" only when the tab is gone from the dock (a moved or redrawn tab is taken over by its next mount); keys typed while the socket connects are sent when it opens instead of dropped.
- `ui_files::build()` is a hash of the installed `index.html` (which names every bundle by its content hash), so reinstalling the same interface does not reload the window.
- `GET /api/ui/build` says `terminals_survive: true`. A page talking to an older core (one that would kill them) does not reload by itself while a terminal is open: it says so once, and the command **Reload the interface** (`ui.reload`) does it when the user wants.
- Not covered: a restart of `atlas-app` still ends the terminals (the core is in the app's process). That needs a holder process outside the app (the Konsole decoupling item below).

Tests: `a_terminal_outlives_a_page_reload_and_ends_when_its_tab_closes` (core, HTTP: same pid after a reconnect, replayed output, "end" kills, the key then starts a new shell), `ui/tests/terminal-reload.spec.ts` (a `sleep 2; echo alive-42` started before `page.reload()` prints into the same tab after it; same pid; closing the tab gives a new shell).

## Focus

The terminal was sometimes hard to focus. Reproduced: with two terminals in the bottom panel, going back to the first one by its tab in the left bar left the keys on the left bar's row — the terminal was still hidden (`visibility: hidden`, the other terminal was in front) when it was given the focus, and a hidden textarea refuses it. The terminal's `focus` now tries again on the next frame when the first try did not land. `ui/tests/terminal-focus.spec.ts` walks every way to a terminal: a click on its text, its left-bar tab, Ctrl+` from the editor, the panel hidden and shown again, a new terminal, back to the first, and then types into it.

## Not done yet
- **A Claude view that does "not look too much like a terminal", with LaTeX.** A terminal cannot draw math: Claude Code is a TUI that paints cells. Real LaTeX needs a different surface — e.g. a Claude pane that reads Claude Code's session transcript (`~/.claude*/projects/<slug>/<id>.jsonl`, streamed as it grows) and renders it as Markdown with KaTeX, with the terminal kept for input, or one built on the Claude Agent SDK. A design question to settle first.
- **Sessions that outlive Atlas** and open in Konsole: options weighed; tmux only if there is no other way.
